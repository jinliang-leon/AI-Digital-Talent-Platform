# 部署说明

本版将 FastAPI Web 与 RQ worker 容器化，复用用户本机 MySQL、Redis、MinIO、Neo4j、Milvus、模型网关和 Ollama。命令从项目根目录执行。

## 1. 已验证运行环境

- Windows / Docker Desktop Linux 容器；Web 使用固定摘要的 Python 3.11-slim 基础镜像。
- 本机开发使用独立 `.venv`，不修改系统 Python；完整依赖锁定在 `requirements.lock`，镜像内单元测试另行验证。
- 本地 MySQL 8.0.27；应用与测试分别使用 `ai_digital_talent`、`ai_digital_talent_test`，数据库字符集 utf8mb4。
- 网页入口 `http://127.0.0.1:8088`；API文档 `/docs`；存活 `/health/live`；就绪 `/health/ready`。

| 服务 | 本机地址 | 容器连接方式 |
| --- | --- | --- |
| MySQL | 127.0.0.1:3306 | DATABASE_HOST_OVERRIDE=host.docker.internal |
| Redis | 127.0.0.1:6379，业务db9、测试db10 | host.docker.internal:6379 |
| MinIO API／控制台 | 127.0.0.1:9000／9001 | 内部host.docker.internal:9000，签名下载地址仍为127.0.0.1:9000 |
| Neo4j | bolt://127.0.0.1:7687，控制台7474 | bolt://host.docker.internal:7687 |
| Milvus | http://127.0.0.1:19530 | http://host.docker.internal:19530 |
| 模型网关 | http://127.0.0.1:20128/v1 | http://host.docker.internal:20128/v1 |
| Ollama | http://127.0.0.1:11434 | http://host.docker.internal:11434 |

## 2. 准备配置和数据库

1. 复制 `.env.example` 为 `.env`，填写本机服务凭据。现有开发机已完成，不要覆盖现有 `.env`。
2. `JWT_SECRET` 使用至少32字符随机值；`INITIAL_ADMIN_PASSWORD` 至少10字符。初始账号名为admin，管理员同时具备HR角色。
3. 通过本机MySQL管理员创建上述两个项目专用库，为本地项目账号授予这两个库的SELECT/INSERT/UPDATE/DELETE/CREATE/ALTER/INDEX/REFERENCES。`DATABASE_URL`、`TEST_DATABASE_URL`采用mysql+pymysql格式；URI中的特殊密码字符需URL编码。
4. 项目账号仅localhost来源，现有Docker Desktop环境已实测可达；不要为省事改成任意来源账号。如在其他机器连接失败，先核查MySQL实际看到的来源，再按确定来源配置。
5. 确认Ollama已有 `bge-m3:latest`，1024维。网关模型标识为 `xingchen/spark-x2.6`；显示名Spark-X2.6，不能用auto替代。

MinIO业务桶默认 `ai-talent-resumes`，测试桶 `ai-talent-tests`；Milvus和Neo4j使用 `PROJECT_NAMESPACE` 隔离。本项目不会覆盖或停止既有基础服务容器。

## 3. 构建、迁移和启动

```powershell
docker compose build
docker compose run --rm web python -m alembic upgrade head
docker compose run --rm web python -m app.cli init-admin --username admin
docker compose up -d web worker
docker compose ps
```

如Docker构建需要当前机器已有代理，可使用：

```powershell
docker compose build --build-arg HTTP_PROXY=http://host.docker.internal:7897 --build-arg HTTPS_PROXY=http://host.docker.internal:7897
```

代理参数仅用于构建，实际模型／Ollama HTTP适配器禁用系统代理自动探测。

迁移当前为0002：0001冻结初始结构，0002扩展中文全文列为LONGTEXT。初始化命令重复运行不会修改已有账号密码或权限。已有库升级使用Alembic，不重复执行完整建表SQL。

仅Web发布127.0.0.1:8088；worker不开放端口，保持单副本。模型输出经格式、原文证据核验后入库；所有必要索引完成才标READY。

## 4. 检查和日常操作

```powershell
Invoke-RestMethod http://127.0.0.1:8088/health/live
Invoke-RestMethod http://127.0.0.1:8088/health/ready
docker compose logs --tail 80 web worker
docker compose stop web worker
docker compose up -d web worker
```

管理员网页“系统管理 → 检查连接”提供七项脱敏连接状态。模型被列出不代表推理一定成功，实际任务和验收报告另行记录。

`docker compose stop`只停止本项目应用与worker，不清理数据库、原文件或基础服务。启动时worker从SQL恢复未投递任务；失败任务在网页手动重试。

## 5. 演示数据、测试和设计快照

```powershell
.\.venv\Scripts\python.exe -m scripts.生成演示数据
.\.venv\Scripts\python.exe -m scripts.导出设计产物
$env:PYTEST_DISABLE_PLUGIN_AUTOLOAD='1'
.\.venv\Scripts\python.exe -m pytest -q -p no:cacheprovider
.\.venv\Scripts\python.exe -m scripts.真实模型验收
```

真实模型验收要求已导入冻结30份简历和5个岗位。`导入演示数据`是本机串行验收工具，可重复复用已完成记录；其直接执行任务时应暂停本项目worker，避免争用同一任务。正常网页上传则由运行中的worker消费，二者选一种处理方式。

测试必须在 `.env` 配置独立 `TEST_DATABASE_URL`；测试自动使用测试桶、Redis db10及 `ai_talent_test` 命名空间，不能回退到业务库。原始调试日志在忽略的 `运行数据/`，可共享的脱敏报告在 `文档/05_测试验收/`。

## 6. 常见故障

| 现象 | 处理 |
| --- | --- |
| 登录503 | 检查本地MySQL、Redis和专用账号；先运行迁移和初始化 |
| 任务长期排队 | 检查本项目worker是否运行，查看SQL任务状态与worker日志 |
| MODEL_UNAVAILABLE | 检查本机网关、指定模型的登录状态和超时设置；不会切换成其他模型伪装成功 |
| MODEL_FORMAT_ERROR | 模型格式或引用两次仍不成立；任务显示失败，可重试或核对原文 |
| OCR_NOT_SUPPORTED | 上传可复制文字的PDF或DOCX；本版不识别扫描件 |
| GRAPH_INDEX_NOT_READY | 当前图节点缺失；暂停worker后执行下面的当前索引重建 |
| 409档案已更新 | 刷新后用最新revision再修改或匹配；禁止覆盖并发更新 |
| 旧简历下载409 | 从人才当前档案下载最新原文，旧原文保留在历史存储但通用下载入口不签发 |

索引恢复只读取项目当前READY事实，不调用云模型：

```powershell
docker compose stop worker
docker compose run --rm web python -m scripts.重建项目索引
docker compose up -d worker
```

默认请求超时90秒，可用 `LLM_TIMEOUT_SECONDS` 调整；真实批量验收会记录使用90秒的情况。worker硬超时600秒，720秒判失联。超时上限不是性能达标承诺，实际时延见验收结果。

首版未附独立基础服务Compose和自动备份恢复系统；跨机器部署需先准备同等依赖。本地HTTP演示使用development配置，生产HTTPS、域名、备份和多副本治理需另外实施。

## 当前网关兼容性实测

本机10Router→Spark-X2.6路径虽返回200并接受关闭思考参数，64token探测仍返回reasoning_content；不能保证已关闭思考。max_tokens与max_completion_tokens均已实测生效。模型请求有间歇超时，当前应用显式限制90秒、格式/引用最多修复一次，并提供真实失败状态。RAG≤30秒目标需要结合最终验收报告判断，不能由“连接正常”推断达标。

对照依据：讯飞官方参数文档 https://www.xfyun.cn/doc/spark/X1http.html ；本机探测是具体网关版本的实测结果，与官方接口直连行为可能不同。
