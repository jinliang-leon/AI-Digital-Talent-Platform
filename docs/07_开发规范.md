# 开发规范

v0.1 · 待评审

- 模块依赖遵循 API → 服务 → 数据接入。Agent 依赖受控工具接口。请求 DTO 与 ORM 模型分开。连接和会话生命周期由依赖注入管理。公共抽象以实际复用为依据。
- Python 使用类型标注、统一 lint 和格式化，前端启用 TypeScript 严格检查。接口、状态流转、权限矩阵和迁移变更同步更新对应设计文档。
- 应用进程使用环境变量和最小权限账号。凭证仅存受控环境或秘密管理工具。日志禁止写原始简历、联系人、认证头、连接串及完整模型提示词。
- 数据库查询使用参数化绑定。输入枚举、过滤、分页和排序字段白名单。高风险操作应用资源级授权、执行确认、审计和防重放。
- 原件使用私有容器、大小和内容签名校验、归档解压限额、受限解析进程和内容识别。上传失败安全收敛，孤立对象由清理任务回收。
- Celery 任务只传不含隐私的业务标识，使用超时、有限重试、幂等键、租约和条件写回。运行状态以 DB 为准。记录可诊断错误码，原始异常留在安全日志。
- 探索性本地开发使用独立环境和合成数据。新依赖先验证版本、许可证和必要性。评审后固定容器镜像及依赖版本。
- 每阶段运行直接覆盖本阶段入口的测试。迁移需要校验空库升级、增量升级和回滚或前进修复预案。敏感字段、权限、任务重试和业务状态变更必须有确定性回归。
- 评审重点检查调用范围、状态一致性、外部发送内容和回滚方式。仅在实际验证后更新完成状态。
