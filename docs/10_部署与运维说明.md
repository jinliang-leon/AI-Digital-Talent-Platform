v0.1 · 目标设计。本项目尚未初始化可执行服务，以下命令和组件待编码后验证。

## 本地运行目标

Docker Desktop Linux 容器或可访问的 Linux Docker 主机。Compose 计划包含 nginx/web、api、worker、dispatcher、postgres（含 pgvector）、redis、minio。Langfuse 以配置选择已批准的实例，开发用合成数据验证真实上报。OCR 安装在 worker 镜像内，覆盖中文和英文。PostgreSQL、对象存储和队列按用途设置持久化。

本轮测得 Docker Compose CLI v5.6.0，当前执行环境连接 Linux 引擎提示 permission denied。第一阶段先核验可访问的 Docker 上下文与 `docker info`，随后验证 Compose 和容器健康，再启动业务服务。

## 拟定部署顺序

1. 复制 .env.example 为开发环境配置，按需填写数据库、MinIO、Redis、JWT、模型及 Langfuse 配置。提交示例占位值。
2. 运行 `docker compose config --quiet` 检查配置。启动 PostgreSQL、Redis 和 MinIO，待健康后创建私有桶。
3. 一次性执行 Alembic 升级和可选的合成数据初始化，通过受控命令创建初始管理员。
4. 使用 `docker compose up -d` 启动 API、worker、dispatcher 和 Web。检查 `docker compose ps`、健康检查与业务日志。
5. 验证上传、队列消费、模型调用、索引和 Trace。环境若缺真实模型配置，AI 路由应返回明确不可用状态。

## 运行与故障恢复

- Nginx 为 SSE 配置禁用代理缓冲和合适的读取超时，应用发送心跳，外部部署接入 TLS 并限制入口速率。
- API 提供存活和依赖就绪探针。队列监控积压、失败率和超时。使用 trace_id 定位解析、检索、工具调用、用量和耗时。遥测按字段白名单发送，禁止原文及敏感媒体自动采集。
- PostgreSQL 定期备份并演练恢复。MinIO 原件备份与数据库备份建立一致恢复点。恢复后检查未完成任务和索引版本，可按数据库记录重新投递与重建索引。
- 发布前对固定集与新迁移做验证，部署时考虑新旧 worker 共存期的任务兼容。回滚前验证数据库兼容，需要时执行文档化的前进修复。
- 运维人员按授权处理失败任务。人工重试会核验任务状态、对象所有权和版本。外部模型不可用时保留手工流程、可访问的原件与已确认记录。
