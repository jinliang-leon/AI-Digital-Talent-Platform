# AI数字化人才平台首版实施计划

> 面向执行代理：使用 executing-plans 在当前会话逐项执行；TDD 先观察失败再实现，最后做一次独立代码审阅。用户已确认设计并要求继续开发，执行方式为当前会话直接实施。

**目标：** 交付可运行、可追溯、中文操作界面的简历解析、人才画像、双向匹配与 RAG 演示平台。
**架构：** 模块化 FastAPI MVC 应用与独立 RQ worker 共用代码；MySQL 为事实源，Redis 负责任务与缓存，MinIO 存原文件，Milvus 和 Neo4j 存可重建索引。
**技术栈：** Python、FastAPI、JWT、SQLAlchemy/Alembic、LangChain/LangGraph、MySQL、Neo4j、Milvus、Redis、MinIO、Docker。
**设计：** [架构与完整设计](../02_设计/架构与完整设计.md)。

## 全局约束

- 全部本地交付物放在 D:/项目/ai数字化人才平台/codex产出；同步既定 GitHub 仓库。
- 文档文件名、内容、网页文字和用户错误提示使用中文；Python 包名、API 字段和配置键使用规范标识。
- 不以 SQLite 替换本地 MySQL；不修改或删除用户既有数据库、容器和其他项目数据。
- 对话模型 xingchen/spark-x2.6，经 http://127.0.0.1:20128/v1；Embedding 为本机 Ollama bge-m3:latest、1024 维。
- 密钥仅放未跟踪的本地配置；不进入文档、Git、接口响应和日志。
- 管理员/HR；30 份虚构简历与 5 个 JD；PDF/DOCX 文本格式；OCR、测评不在首版。
- 硬条件 FAIL 排除、UNKNOWN 单独需复核；备注不进入匹配/RAG；事实修改需原文证据。
- Python 容器运行时 3.11；本机测试在独立虚拟环境使用可用解释器，兼容性以实测为准。

## 审阅重点

1. 过期/停用/降权账号、Cookie CSRF、下载与后台接口越权 → 任务 1/8。
2. 文件签名伪造、DOCX 压缩炸弹、扫描 PDF、模型提示注入 → 任务 2。
3. 重复投递、worker 中断、旧向量和新事实版本并存 → 任务 2/4。
4. UNKNOWN 不应混入 eligible；没有原文依据的编辑和备注不可污染评分 → 任务 3/5。
5. RAG 引用伪造、无答案问题、模型/索引不可用应明确失败 → 任务 6/8。

## 文件职责

- app/config.py、db.py、models.py：配置、连接、持久化实体。
- app/controllers/：auth、talents、jobs、search、admin、web 路由；仅处理 DTO、鉴权和 HTTP。
- app/services/：鉴权、文档解析、处理图、索引、档案、匹配、检索。
- app/adapters/：模型、Embedding、对象存储、向量与图数据库。
- app/schemas.py、templates/、static/：响应视图、中文模板、样式与交互。
- app/worker.py、cli.py：后台消费、补偿调度、初始化和演示数据导入。
- migrations/、scripts/、tests/：迁移、可复用运维脚本、单元/集成/端到端测试。
- 文档/01_需求～05_测试验收：各软件开发阶段的可审阅产物。
- 样例数据/：虚构简历 PDF/DOCX、JD、人工标注与测试问题。
