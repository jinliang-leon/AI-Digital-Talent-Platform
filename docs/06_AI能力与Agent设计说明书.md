# AI 能力与 Agent 设计说明书

> 第一阶段只实现招聘基础业务及其权限、文件和审计。以下 Workflow 与 Agent 均为后续设计，当前无模型调用、问答或虚拟 AI 返回。

v0.1 · 待评审

| 能力 | 编排与输入输出 |
| --- | --- |
| 简历解析 Workflow | 类型与资源校验 → 原件保存 → 文本提取 → 必要时本地 OCR → 规范原文锚点 → 隐私过滤与结构化抽取 → 校验与重复提示 → 等待人工确认 → 入库与索引 |
| 岗位分析 Workflow | 招聘描述或 JD → 知识检索 → 结构化要求、冲突及缺项 → HR 确认为不可变修订 |
| 岗位证据分析 Workflow | 固定岗位修订、确认版简历及可见知识 → 逐项证据、未找到或待核实 → 人工审核 |
| 人才检索 Agent | 将自然语言和对话补充转为 SearchPlan，按约束调用业务检索，返回授权范围内的证据和查询解释 |
| 面试辅助 Agent | 调用只读工具取得岗位要求、简历证据及专业知识，生成问题、考察点、参考答案和追问，面试官编辑后保存 |
| 知识问答 Workflow | 权限内知识检索与重排 → 引用生成与验证 → 无充分证据时说明信息不足 |
| ChatAI 主控 Agent | 校验请求 → 恢复会话 → 问题改写与意图路由 → 对应工具或 Workflow → SSE、引用与用量 |

### 结构化提取和证据

Schema 为可空字段和 evidence[]，每项包含 version_id、定位类型、页码或段落号、块标识、偏移及引文。PDF 使用页面和文本位置，OCR 使用页面与识别框，TXT 使用行号，DOCX 使用段落或表格定位。原文规范化后保留定位映射。应用校验证据确实位于指定版本，校验失败标为待复核。人工补录记录录入来源，证据视图仅提供授权者可见片段。

PDF 使用文本提取与逐页 OCR 回退，DOCX 读取正文与表格，TXT 识别限定编码。结构化提取前用本地规则屏蔽非必要个人信息，联系方式本地提取并交由人工确认。文档内容仅进入数据槽，模型输出经 Schema 和服务规则验证；解析工作流不给模型工具权限。

### 混合检索

SearchPlan 只允许技能、站点、岗位、经验等白名单条件。显式过滤条件优先，问题改写不能放宽权限。先形成可见版本集合，然后分别执行中文关键词和语义检索。以候选人最佳切片计算各路排名，RRF 默认 k=60，合并后对前 30 项脱敏证据重排，按候选人去重并保留多条引文。具体参数由评估集校准。外部重排失败时可回落到 RRF，并标注检索模式。排名仅用于检索相关性。

### 工具和记忆

主控使用有限工具集，如 search_candidates、get_job_progress、get_resume_evidence、query_recruitment_kb、draft_interview_questions。服务注入身份，每次执行和引用渲染重新授权。限轮次、耗时和文本预算。资料、工具返回及会话历史均按不可信输入处理。岗位、候选人或状态写入通过独立 API 和人工确认，ChatAI 可生成建议内容。

会话由 PostgreSQL 保存，工作上下文取最近消息与带版本摘要，Redis 可用作短期缓存。权限发生变化时重新装载合法引用。Token 消耗、提示词版本、模型 ID、耗时、状态和脱敏统计进入 Trace。模型输出不得包含录用结论、综合录用分数或与岗位无关的个人属性。

### 模型与实现

评审后锁定 LLM、Embedding 和 Rerank 的模型标识、维度、服务区域与数据策略。Embedding 变更走重建、验证、切换。PromptManager 以 Git 模板和版本登记为初版，按需抽象 BaseLLM、工具及工作流契约。LangGraph 仅用于需要条件路由、动态工具回合和明确状态的链路；OCR 和人工确认依赖业务任务与状态持久化。MCP 保留为对接选项。
