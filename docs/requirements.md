# AI数字化人才平台：需求基线

状态：需求访谈中，待补充并确认首版范围；当前不是最终设计或开发计划。
记录日期：2026-11-10（Asia/Shanghai）

## 1. 已确认的业务目标

面向企业 HR，解决传统简历筛选中关键词检索容易漏人、匹配粗糙、简历整理耗时的问题。

第一版用于课程／作品演示，重点是完整跑通招聘流程。这是交付场景；产品面向的业务用户仍为企业 HR。

## 2. 用户提出的能力范围

- 简历上传、结构化解析。
- 生成人才画像与人才档案。
- 简历向量化入库。
- 岗位 JD 与人才双向智能匹配。
- RAG 简历检索。
- 人才管理与标签管理。
- JWT 鉴权与 RBAC 权限管控。
- 智能测评为可选能力。

用户允许挑选部分功能实施，无需首版完成全部能力。首版功能取舍尚未确认，不能将上述候选范围视为全部已承诺交付。

业务实体：人才简历、岗位 JD、用户账号、标签、人才向量档案。

## 3. 技术栈硬性约束

| 领域 | 指定技术 |
| --- | --- |
| 开发语言 | Python |
| Web 框架 | FastAPI |
| 鉴权 | JWT |
| 代码组织 | MVC 架构 |
| AI 应用与流程编排 | LangChain + LangGraph |
| 业务数据库 | 用户本地 MySQL |
| 图数据库 | Neo4j |
| 向量数据库 | Milvus |
| 缓存 | Redis |
| 简历原文件存储 | MinIO |
| 部署 | Docker 容器化 |

本地 MySQL 是明确约束；不能擅自替换为 SQLite、PostgreSQL 或仅使用容器内 MySQL。各组件的具体职责、版本、连接方式与部署参数将在架构设计阶段明确。
