# AI数字化人才平台：需求基线

状态：两轮主要需求已确认；配套设计已形成草稿，尚有两项业务边界待确认。
记录日期：2026-11-10（Asia/Shanghai）

## 1. 已确认的业务目标

面向企业 HR，解决传统简历筛选中关键词检索容易漏人、匹配粗糙、简历整理耗时的问题。

第一版用于课程／作品演示，重点是完整跑通招聘流程。这是交付场景；产品面向的业务用户仍为企业 HR。

## 2. 用户提出的能力范围

- 简历上传、结构化解析。
- 生成人才画像与人才档案。
- 简历向量化入库。
- 岗位 JD 与人才双向智能匹配。
- RAG 简历检索。
- 人才管理与标签管理。
- JWT 鉴权与 RBAC 权限管控。
- 智能测评为可选能力。

用户允许挑选部分功能实施，无需首版完成全部能力。

### 2.1 已确认的首版范围

- 四项核心能力：简历上传与结构化解析、人才画像、岗位匹配、带简历来源的 RAG 检索。
- 配套基础人才管理、JWT 鉴权与 RBAC 权限管控。
- 交付可操作的网页，演示“上传简历 → 查看画像 → 创建岗位 → 查看匹配和检索结果”的完整流程。
- 支持可复制文字的 PDF 和 DOCX；扫描件 OCR 留到后续。
- 对话模型使用用户指定的 OpenAI 兼容网关 `http://127.0.0.1:20128/v1`；Embedding 使用本机 Ollama 的 `bge-m3:latest`（1024 维）。这替代第一轮中“云端 Embedding”的接入方向。
- 智能测评不在首版交付范围。

### 2.2 第二轮已确认的业务行为

- 首版设置管理员、HR 两类角色。管理员管理账号与角色；HR 操作简历、人才、岗位、匹配和检索。
- 准备 30 份虚构简历与 5 个岗位 JD，覆盖不同技能、经验和匹配程度，不使用真实个人信息。
- 支持“岗位找人才”和“人才找岗位”，展示排序、匹配依据、能力缺口、简历原文证据，由 HR 人工判断。
- 匹配依据聚焦岗位相关技能、经历和项目证据。
- 对话接口及访问凭据由用户提供；默认对话模型由用户指定为 Spark-X2.6，实际请求标识为 `xingchen/spark-x2.6`。仓库仅记录接口地址和配置字段，不记录真实凭据。
- 用户所称本地“bge-3”经环境勘察确认为 `bge-m3:latest`，服务为 Ollama，端口 11434。

业务实体：人才简历、岗位 JD、用户账号、标签、人才向量档案。

## 3. 技术栈硬性约束

| 领域 | 指定技术 |
| --- | --- |
| 开发语言 | Python |
| Web 框架 | FastAPI |
| 鉴权 | JWT |
| 代码组织 | MVC 架构 |
| AI 应用与流程编排 | LangChain + LangGraph |
| 业务数据库 | 用户本地 MySQL |
| 图数据库 | Neo4j |
| 向量数据库 | Milvus |
| 缓存 | Redis |
| 简历原文件存储 | MinIO |
| 部署 | Docker 容器化 |

本地 MySQL 是明确约束；不能擅自替换为 SQLite、PostgreSQL 或仅使用容器内 MySQL。各组件的具体职责、版本、连接方式与部署参数将在架构设计阶段明确。
