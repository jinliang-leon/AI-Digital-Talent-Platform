# 需求规格说明书

> 第一阶段确认规则：仅设置系统管理员、HR 和面试官三种角色。管理员不自动访问候选人隐私数据。联系方式及敏感原件读取、重开终态均需 HR 额外授权。面试官只可读取其指派下的岗位、候选人和人工确认脱敏简历。下表的业务负责人为原需求中的协作者职责，本期无需创建对应的登录角色。

v0.1 · 待评审

## 用户与权限

| 角色 | 访问边界 |
| --- | --- |
| HR | 按人才库和岗位授权读写，具备相应属性权限才可查看联系方式、下载、导出或发起删除 |
| 业务负责人 | 查看获授权岗位与相关应聘，维护岗位需求草稿、查看证据并提交业务意见 |
| 面试官 | 查看被指派面试的岗位与脱敏材料，编辑相应题目和反馈 |
| 系统管理员 | 用户、角色、权限、运行配置与审计管理。候选人读权单独授予 |

权限检查涵盖角色、资源关系和字段，适用于 API、检索、ChatAI、文件流、导出和任务重试。初期单企业，业务部门仅作为岗位字段。使用虚构简历与测试账号，真实数据启用前由企业确认处理依据、保留期限及模型服务配置。

## 功能规格

| 编号 | 可验收行为 |
| --- | --- |
| F01 工作台 | 实时按可见范围统计在招、人才库、今日上传、待解析、待审核和待面试。支持岗位进度、动态、待办和助手入口 |
| F02 岗位 | 创建、编辑、查询、关闭，保存部门、人数、职责、必备和优先技能、专业能力、经历、负责人和状态。AI 输出 JD 草稿、结构化要求、术语及冲突提示，人工确认后发布 |
| F03 简历 | PDF、DOCX、TXT、JPG、PNG，支持单份及批量上传、OCR、异步状态、失败重试、证据对照、重复提示及人工修正 |
| F04 人才库 | 搜索、筛选、分页、详情、原件、版本、技能与经历、历史岗位与面试、备注。支持受权导入、导出、合并和删除 |
| F05 搜索 | 自然语言及显式筛选、续问补条件、中文关键词和语义混合、SQL 权限过滤、重排、去重、原文证据 |
| F06 岗位证据 | 逐项展示证据、不明确或未找到状态，提供追问。输出中排除岗位能力无关属性与录用分数 |
| F07 面试 | 支持难度、项目追问、技能与业务场景、参考答案、考察点、追问、人工改题、反馈记录和 AI 摘要 |
| F08 流程 | 按应聘记录推进状态，人工确认关键状态并写审计 |
| F09 知识库 | 上传、解析、索引、检索测试、分类与授权、RAG 引用、版本更新和删除 |
| F10 助手 | 提供招聘进度、人才查询、简历证据、面试题、制度和术语等入口，具备会话、路由、SSE 和引用。业务写入走已授权的独立操作 |
| F11 管理与评估 | 登录、用户与角色、操作审计、任务状态、Langfuse Trace、固定数据集回归与发布闸门 |

## 页面与交互

九个菜单对应招聘工作台、岗位、人才库、简历解析、AI 人才检索、面试、招聘知识库、AI 助手和系统管理。岗位详情展示要求、候选人流程和面试安排。简历确认页左右对照原文和字段，证据可定位。统一加载、空态、任务重试、无权限及错误回执。所有工作台统计以数据库为准，按 Asia/Shanghai 划分业务自然日。

## 业务规则

同一候选人可以申请多个岗位。文件哈希命中提示既有上传，候选人疑似重复由人工确认归并。AI 生成内容可编辑并保留生成来源。招聘决策交由授权人员。后续接入 ATS 通过数据适配器，首版数据来自人工录入、上传及系统使用记录。
