# AI 隐私边界与历史数据治理

## 实际边界

| 入口 | 数据与权限控制 |
| --- | --- |
| ChatAI | `chat.stream()` 执行角色、会话和对象检查，再调用 `clean_model_text()` 写入。会话标题、历史问题与近期模型上下文也清理。后台工作和 SSE 收尾重新检查登录状态。 |
| Tool Calling | 模型只输出 `RecruitmentAction` 的有限意图与改写文本，资源 ID 来自请求并通过现有业务权限。人才工具只给对话匿名显示和简历证据，招聘岗位进度按当前对象范围重算。工具结果不作为另一个通用模型上下文。 |
| RAG | 当前授权版本经 `searchable_chunks()` 清理。模型只见局部编号和引文，并仅返回编号。候选引文必须同时包含在净化后原片段及原始片段中。回复中的标题、版本及出处由服务端恢复。 |
| 向量 | 新知识库词项向量取自脱敏视图，旧版本按脱敏视图重算用于检索。Worker 检测待写入的简历引文，含已知敏感模式的输入终止索引；模型 Embedding 同时受全局开关及数据授权控制。 |
| 原件与联系信息 | HR 的原件、联系方式权限与职业资料查看分开。联系方式仍通过 Fernet 加密列和受控端点，面试官通过分配范围与脱敏文件权限查看获准材料。 |
| Langfuse | 仅发送固定 Span 名称和已声明的计数、用量、状态和标识字段。标准标签还检查可疑内容及固定枚举。原文和异常消息不进入 OTLP。 |

`core/privacy.py` 的模式识别常见邮箱、手机和证件号、中英带地址标识或街道门牌文本，以及既有资料指令标记。遮蔽用等长空格，保持原文偏移。规则不能识别所有人名、无标签地址、跨版面 OCR 片段和隐晦表达。授权的知识材料和简历仍需人工检查，尤其是模型服务不在本机时。完整的简历原件和知识版本保留在受平台权限控制的存储。

## 历史记录治理流程

部署后，旧聊天记录保留原值；读取时构造项目安全视图。旧向量与旧文档数据在存储中也可能仍包含风险。下列流程使用隔离的合成副本验证，生产执行须获授权并安排维护窗口。

1. **确定对象和审批范围。** 责任人记录范围和理由，包括 `chat_sessions.title`、`chat_messages.query/result`、需要重算的 `resume_chunks`、`knowledge_revisions.chunks` 与旧面试提纲。对必须保留的业务档案和证据版本单独审批。
2. **备份并验证恢复。** 只使用约定的加密、受访问控制的备份位置。SQLite 使用协调过的数据库 Backup API 或在暂停写入、处理 WAL 后生成一致副本；PostgreSQL 使用数据库维护方提供的一致备份。若范围包含对象或向量，登记同一时间点的对象清单和向量来源。先在临时环境验证备份可恢复。备份路径、校验和、保留期和审批 ID进入运维记录，内容不输出到 GitHub。
3. **预览。** 使用只读账号或独立快照，按主键分批运行与应用一致的脱敏函数。审查记录只保留表、字段、批次、匹配类型、变化数量及缺失引用计数。若须逐行授权，将不含原文的记录 ID 和原行版本存在受控内网。预览同时检查业务联接、引用、索引条数和角色授权。
4. **审批后变更。** 先在副本复验，记录审查人和计划。正式更新仅改已批准范围，采用行版本或原值摘要条件及有界事务。重新生成脱敏向量并复查引用，只有通过验收后才切换索引。失败时按批次停止或回滚。禁止覆盖用户同期提交。
5. **审计与撤回。** 记录运行配置、脱敏规则版本、处理数、跳过数、失败原因和验证结果。恢复从批准的备份按窗口操作，并核对并发新增记录。到期清理通过新的审批处理。

本流程没有自动批量改写入口。应用部署、迁移和读取操作均不会运行上述历史数据变更。
