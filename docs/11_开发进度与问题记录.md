- `backend/app/ai_resume/documents.py` 支持 TXT、DOCX、PDF、JPG 和 PNG 的文本提取分支，按输入保留行号、段落号或页码。无文本层的 PDF 和图片可调用受超时约束的 Tesseract OCR。
- `backend/app/ai_resume/structured.py` 定义职业信息提取 Schema，验证模型引用的块和原文跨度，默认拦截未获外部处理授权的请求。初步去除联系方式和已知敏感标签，仍需要经审批的数据策略。
- `backend/app/core/ai_client.py` 提供 OpenAI 兼容结构化请求、失败分类与 Token 用量返回。
- `requirements-resume.txt` 声明简历提取所需的 Python 依赖。`tests/test_resume_components.py` 增加纯文本、DOCX、图片 OCR 合约、证据与模型错误测试，其中 HTTP 模型测试使用测试传输层。

## 重要技术决策

| 决策 | 依据与影响 |
| --- | --- |
| 三种角色加 HR 额外授权 | 角色控制招聘、面试或系统管理。联系方式、敏感简历和重开流程独立控制 |

| 先提供单份二进制上传 | 可以限制实际请求字节数。后续批量解析端点仍采用文件批次及异步任务 |
| 前端采用原生 ES Modules | 当前环境 npm 镜像处于离线模式且缺少 Vue 缓存。第一阶段使用不依赖 npm 下载的 Node Web 服务、中文界面及同源代理 |
| ric-train 保留为参考 | 调研其模型接口、工具 Schema、Agent 循环与中间件、ChatAI 审核与改写、会话记忆及 SSE。当前沿用分层配置与模块边界，自身业务不导入脚手架模块 |
| 显式区分 Compose 与本地模式 | Compose 与本地使用独立持久层。SQLite 与磁盘文件本地模式返回 local_only，以便本机验收时区分真实基础设施状态 |
